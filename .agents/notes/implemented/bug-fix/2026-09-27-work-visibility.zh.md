# Agent Note: Flutter 客户端的作品可见性

Status: implemented

[English](2026-09-27-work-visibility.md) | 中文

## Problem

Flutter 客户端保存了全局 R18 设置，但 Rust 列表响应仍会包含受限作品。小说列表还可能包含服务端标记为不可见的条目。显示这些内容会破坏现有的内容规则，也可能让小说详情页面无法正常使用。

## Decision

Rust 接口层在转换响应时过滤插画和小说列表。每次获取分页数据时读取当前的 R18 设置；关闭 R18 时移除 `x_restrict` 大于零的作品；始终移除 `visible` 为 false 的小说。用户明确选择作品编号时，插画和小说详情请求直接读取该作品。R18 设置变化后，Flutter 首页重新加载访问过的内容流。共用分页网格遇到过滤后没有可见条目的页面时，继续使用服务端游标获取后续页面。

## Alternatives considered

**在每个页面组件分别过滤。** 当前与未来的列表页面都需要重复实现同一条内容规则，容易遗漏。

**过滤后遇到空白页面就停止分页。** 服务端可能返回整页受限条目，后续页面仍有可见作品。此时停止分页会隐藏后续作品。

## Consequences

每次转换列表响应时都会查询设置数据库。更改 R18 设置会重建访问过的内容流，并获取当前允许展示的作品。如果连续多页都被过滤，客户端会继续请求，直到取得可见作品或用尽分页游标。

## Verification

使用当前登录状态运行发现页面探针，对照真实 R18 排行响应与 Rust 过滤结果，并记录条目数量。Rust 编译和 macOS 构建验证接口与 Flutter 的连接。
