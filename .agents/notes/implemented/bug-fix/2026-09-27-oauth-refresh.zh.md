# Agent Note: macOS 授权令牌刷新连接

Status: implemented

[English](2026-09-27-oauth-refresh.md) | 中文

## Problem

macOS 系统代理有时是连接 Pixiv 授权令牌服务器的唯一可用路径。Rust 令牌客户端此前依赖进程中的代理环境变量，而从访达启动的应用未必拥有终端会话的环境变量。授权刷新响应还可能把用户编号写成 JSON 字符串。刷新错误的具体原因被隐藏后，访问令牌过期会表现为笼统的登录失败。

## Decision

授权令牌请求启用现有 `reqwest` 客户端的 macOS 系统代理功能。ECH 配置查询、ECH 接口传输和图片 CDN 客户端明确绕过代理，保持各自的直连方式。令牌客户端设置连接超时和请求超时。`serde` 接受数字或数字字符串形式的授权用户编号。访问令牌刷新返回包含原因的错误，写入钥匙串失败时也将错误交给调用方。

## Alternatives considered

**依赖终端的代理环境变量。** 访达不会继承终端会话的代理配置，应用行为会受到启动方式影响。

**读取 `scutil --proxy` 并在应用代码中组装代理地址。** `reqwest` 已提供操作系统代理功能。再写一套解析逻辑会重复它的平台处理。

## Consequences

进程环境没有定义代理时，授权刷新使用 macOS 代理设置。接口与图片请求继续使用现有的 ECH、QUIC 和图片 CDN 直连路径。授权服务器无法连接、授权响应格式错误或钥匙串写入失败时，需要刷新的请求会返回具体错误。

## Verification

在启用系统代理的 Mac 上，清除探针进程的代理环境变量后，个人页面探针从钥匙串恢复登录状态并完成真实令牌刷新。探针随后读取个人资料、头像、两类收藏、已发表作品及作者收藏。Rust 编译与 macOS 构建验证客户端配置。
